What is Attributor?

Attributor is a scientific web platform dedicated to the attribution of molecular formulas from mass spectra. It combines a compute engine written in Rust and compiled to WebAssembly (Attribrustor), heavy processing executed outside the main thread, and a scientific interface built on a visual, interactive data-flow. Everything runs in your browser, with nothing to install: import your data, assemble your processing pipeline and explore the results.

Main features

⚡ Rust / WebAssembly compute

Numerical kernels compiled to WebAssembly process spectral data quickly, directly in the browser.

🧵 Non-blocking compute

Heavy operations run in dedicated workers, so the interface stays responsive even on very large datasets.

🧮 Adaptive compute pool

Tasks are distributed across several workers according to the browser capabilities, with a queue and a JavaScript fallback if needed.

🔗 Interactive data flow

Add nodes, move them and link the steps of your analysis. The pipeline runs, updates and clearly visualises how data propagates.

📈 Integrated WebGL rendering

Explore XY data in interactive WebGL plots designed to keep large datasets fluid while panning and zooming.

🔬 Peak picking

Two stages in one node: 0D persistent homology decides which points are peaks, then a statistical width filter removes the broad structures that are not real peaks.

🧭 Formula-based Kendrick

Type a chemical formula, and every linked spectrum is rescaled around that m/z and reported as a mass defect — homologous series collapse onto one another.

📂 Flexible import

Load delimited text files with configurable separator and columns, or convert raw .raw files through the msConvert service. Direct native .raw import is also available via the thermorawfile Rust crate (no .NET/DLL required).

💾 Portable sessions

Export and import the complete pipeline as JSON, with session versioning and faithful restoration of the data structures.

↩️ Risk-free experimentation

Undo and redo every action through a complete history, tune parameters and compare the results of your scenarios.

🎯 Exhaustive attribution

A mixed-radix sieve enumerates every combination of your groups inside a ppm window — no sampling, no heuristic — and keeps the best distinct readings per peak, ranked by log-probability.

🌲 Measurement network

Link peaks whose gaps match reference masses, take the minimum spanning forest, cut it on the weight curve, merge trees by their stoichiometric difference and propagate formulas from any root you click.

🎛️ Mass calibration

Fit an error surface (m/z × intensity) from the attribution's own ppm errors and apply the correction to every linked spectrum, with residuals and the fitted surface on screen.

💬 Room chat

A chat node joins a WebSocket room — by default the page's own host — for discussing a session with whoever else is looking at it.

Technical documentation

This section is the reference for the Attributor processing nodes. For each node it documents its purpose, its inputs and outputs, the constraints it enforces, and the way its data is laid out in memory.

Global conventions

Wave data layout

A Wave is a typed-array container. Its dims property lists the size of each dimension, and degree is the number of dimensions. The core is stored non-interleaved: the first dimension is the fastest-varying axis. 

new Wave(pointCount, 2)   // 2D wave: dims = [pointCount, 2]

core = [ x0, x1, x2, ..., y0, y1, y2, ... ]

core[i]              // X of point i
core[pointCount + i]  // Y of point i
index(i, 0)          // X of point i
index(i, 1)          // Y of point i

This is the only supported layout for a 2D wave. Interleaved data such as [x0, y0, x1, y1, ...] is never produced and never expected.

A 1D wave is declared as new Wave(n) and its core is simply [y0, y1, ...].

Compute layer

  • Numerical kernels are written in Rust and compiled to WebAssembly.
  • Kernels run inside dedicated workers, never on the main thread.
  • Kernels exchange only flat Float64Array buffers — never arrays of objects or nested pairs.
  • Output buffers are transferred (zero-copy ownership transfer) back to the UI thread.
  • A JavaScript fallback implements the same semantics if WebAssembly or workers are unavailable.

Peak picking H0 width filter

Answers one question — which of these points are peaks — in two stages, both in Rust. The first is 0D persistent homology: it detects sub- and superlevel structures, pairs each with a birth and a death, and keeps the points that survive a classifier line. The second measures the half-height width of each surviving peak on the original profile and removes those that are out of the width population of the spectrum itself.

The two stages answer different questions, and are deliberately independent. Persistence asks is this a local maximum of the filtration? The width filter asks is this feature at the resolution scale of the instrument? A peak can be highly persistent and broad — an intense island of background — or weakly persistent and narrow — an adduct sitting in the noise. Neither criterion subsumes the other, which is why the node runs both.

Item Specification
Inputs 1 input — one 1D or 2D wave, or several at once.
several links more than one link may target input 0, and one link may carry several waves. One wave behaves exactly as below; several are treated as one batch — see Multiplexing.
Outputs 1 output — the peaks that survive both stages, as a non-interleaved 2D wave [X…, Y…]. Multiplexed: one such wave per input wave, in input order.
The birth/death pairs and the input indices are internal: they feed the persistence diagram and the width measurement, and never leave the node. There is no second slot — an output nothing consumes is a cable you would have to wire by hand.

Stage 1 — 0D persistent homology

  1. The kernel reads the Y block of the input core directly (no copy, no interleaving).
  2. For superlevel, points are activated by decreasing Y; for sublevel, by increasing Y. Ties are broken by increasing X.
  3. Union-find merges adjacent components as the filtration level changes.
  4. Each input point yields one persistence pair: a birth equal to its own Y, and a death recorded when its component merges. The surviving component keeps death = 0.
  5. Results are reordered by increasing X, so the output is always X-sorted.
  6. The default slope is computed from the pairs, clamped to [1e-9, 1 - 1e-12].
  7. The filter keeps every pair with death <= slope × birth, and returns the corresponding original points with the index each one has in the input wave. That index is the only route back to the profile, and stage 2 needs it: a kept point is otherwise nothing but a coordinate, with no way to find the samples on either side of it.

Stage 2 — anti-radio, a width test on the raw profile

A Fourier-transform peak is narrow at the instrument's resolution scale; a broad structure — background, an isotope shoulder, an extended chemical background — is not. The half-height width is the classical criterion, and the prototype this node descends from counted it in samples. Expressing it in ppm instead removes the dependence on acquisition sampling, and comparing it to a measured reference instead of a fixed one removes the dependence on the instrument.

  1. Self-limiting half-height scan. From the apex, the kernel walks outwards on both sides while the profile stays above height / 2, and stops when it does not. There is no analysis window and therefore no window parameter: the signal says where the peak ends. The level is relative to the peak's own height, so a peak at 3 % of the base peak is judged by its own shape and not by the base peak's.
  2. Width in ppm. The measured span is divided by the peak's own m/z and scaled by 106. This is what makes the statistic dimensionless and independent of the sampling: a peak measured on a denser axis gives the same number, not a smaller one.
  3. Robust reference. The median of the measured widths is the width reference — an empirical estimate of the instrument's resolution on this spectrum, not a tabulated value. The spread is 1.4826 × MAD, the usual conversion from a median absolute deviation to a standard deviation. Both are robust by construction, so the wide structures the filter exists to catch cannot inflate the very threshold meant to catch them.
  4. Threshold. A peak is rejected when width > reference + z × σ. Because the threshold is an offset from a measured spread rather than an absolute number of samples, the false-positive rate is a property of the observed dispersion and not of how many peaks the file happens to contain.

A peak is unmeasurable — and therefore kept — when the scan reaches a border of the spectrum, when its height is not positive, when its index is outside the input wave, or when its m/z is not positive. It also leaves the reference population. The alternative, dropping what cannot be measured, would reject peaks on a guess; a peak nobody could measure is not evidence of anything.

Below 8 measurable widths there is no population to describe, and the filter declines to judge: nothing is rejected, and the node says so rather than looking like it found nothing suspicious. Below that count a median and a MAD are not an estimate of anything.

Two limitations are worth stating plainly. The width is taken at half height without a baseline subtraction, so on a spectrum with a high background a peak barely above the noise has an inflated width; a local signal-to-noise gate, or a morphological baseline at the peak's own scale, would address it. And the reference is a single median over the whole m/z range, which assumes a resolution that does not vary across it — reasonable for a fixed detection frequency, not for a frequency sweep, where the filter is biased at both ends of the range.

Choosing z

The z is a threshold in units of the robust spread, and there are two ways to arrive at one.

The convention. z = 3 is the default: roughly three robust sigmas above the median width. It is a statistical convention, not a setting fitted to your data, and that is what makes the node usable with no tuning.

Reading it from the spectrum. The Guess control measures the largest gap between consecutive sorted widths, in robust sigmas, and returns half of it. When a spectrum holds both sharp peaks and broad ones there is a gap between the two populations, and the cut belongs in that gap; half of it puts the threshold where the wide population starts, which is what the filter is for.

That gap is only believed when it clears the noise: a unimodal set of widths still has a largest gap, and acting on it would place the cut inside the real population and throw away half the peaks. A gap must exceed the typical step between neighbours by a factor of 8, and the guess falls back to the convention otherwise. It always returns a usable value.

A z read this way can be large — hundreds — and that is the honest answer rather than an anomaly: when the bulk of the widths is extremely tight, a threshold anywhere near it would keep the whole wide population. A reading of exactly 3 is treated as no reading: the kernel returns the convention both when it measured a gap and when it had no population to measure, and the two are not distinguishable from the number alone, so the automatic reading keeps trying on the next resolve.

Automatic by default. While zSource is convention — that is, while nobody has chosen a value — the node reads z from each resolve and the filter runs with it. Typing a value, or pressing Guess, settles the question permanently and the reading stops. This mirrors the classifier's null slope: both parameters are “auto until you decide”. zSource is serialised with the session, so a session saved before it existed is read as convention, which is what it was.

Interactive behaviour

  • The persistence diagram shows kept pairs in green and discarded pairs in grey, on a WebGL canvas. It describes stage 1 only: the width filter acts on the profile, not on the diagram, and has no representation there.
  • The two stages sit under separate captions, Persistent Homology and Anti-radio. They are independent decisions and read as such; each carries its own controls and its own readout.
  • The anti-radio readout shows the width reference in ppm and the kept / candidates ratio. The reference is the number to watch: it is the instrument's measured width on this spectrum, and it can be checked against a datasheet. A dash means no reference could be measured, which is not the same as “nothing found”.
  • The classifier line is an SVG overlay drawn through the origin: death = slope × birth.
  • Clicking the diagram places the classifier at that location and recomputes the filter.
  • Changing the slope or the z never recomputes H0: only the classification and the width kernels are re-run, and the width scan is skipped entirely when the input has no mass axis.
  • The numeric fields are the only elements that shrink when the panel is narrow: the Guess buttons and the readouts keep their width, so they are the last things to be pushed out of sight.

Error conditions

  • error a link targeting an input the node does not have.
  • floating no wave connected yet, or the connected value carries no usable wave.
  • stage 2 skipped the input is a 1D wave, so there is no mass axis and a width in ppm cannot be computed. The classified peaks are published unchanged and the readout shows a dash. The stage is not reported as having found nothing: it never ran.
  • non fatal if the width kernel fails, the classified peaks are still published. They are valid work, and losing them to a failure in the second stage would be the worse outcome.
  • fallback WebAssembly or workers unavailable: an equivalent JavaScript implementation is used, with the same constants and the same decision rules.

Session behaviour

The classifier slope, its marker position, the filtration mode, the z and the zSource are serialised with the session and restored on reload, so a fitted slope and a hand-chosen z are never silently recomputed.

Legacy sessions are migrated automatically, and the node has carried three names. Sessions referring to the former PersistentHomology0DNode — with or without the input-index output — and to the separate AntiRadioNode all load as a single Peak picking node with one input and one output. A separate anti-radio node is dropped along with its links: keeping the cable would leave a peak-picking node reading from another one, and the width filter would run twice.

Multiplexing

Several links on input 0, or one link carrying several waves, are the same request: treat these data the same way. What decides is not the number of cables but the number of waves that reach the anchor.

  • One wave — the case this node was built for, and it is unchanged: the slope field, the z field, the Guess buttons and the click on the diagram all work as before.
  • Several waves — every input is resolved with the defaults, one after another: the classifier slope is the kernel's own fit for that spectrum (or the centroid guess when it has none), and the width threshold z is read off that spectrum's peak widths. None of this is a per-spectrum setting, which is the point: a multiplex is a request for the same treatment N times, not for N panes of settings.
  • No reading is stored. Neither the guessed slope nor the guessed z is written into the node's parameters. They are per-spectrum facts, and the node has one slope field and one z field: writing the first spectrum's guess into them would have every other spectrum cut by it on the next resolve. The fields keep their own values, and the panel shows what the first spectrum was cut with.
  • The slope and z fields, and both Guess buttons, go grey, and a click on the diagram no longer places the classifier — each spectrum is cut by its own line, so one line could only ever move one of them. The Lin/Log switch stays live: it is how the diagram is drawn, not what the node decides.
  • The output is one peak list per input wave, in input order, each carrying its own slope, its own z and the source title of the spectrum it came from. The diagram shows the first spectrum — one diagram cannot overlay N clouds honestly — and the counter reads N entrées · kept/total, summed over the batch.
  • One input the kernel fails on is one broken result, not a dead node: it is logged and the resolve carries on. error appears only when nothing came out.

The guess runs after the classification, never before: it measures the classified peaks at their input indices, so those indices must already exist. Placing it there is also what keeps a resolve at a single classifier run instead of two. The guess returns one number and allocates nothing, for the same reason the trimmer's does — the shell only needs the value.

Trimmer intensity

Removes the points of an input wave whose intensity falls outside a pair of bounds, and emits the surviving points as a new wave. The two bounds are the node's own state: they are drawn in the frame and dragged directly, and the output always reflects them.

The method does one thing only — it decides where the lower bound is initially placed. Once a bound is finite it is authoritative: the trim uses it, and the method never acts as a floor over it. This separation is deliberate and is the reason the guess and the cut are two distinct kernels.

Multiplexing

Several links on input 0, or one link carrying several waves, are the same request: treat these data the same way. What decides is not the number of cables but the number of waves that reach the anchor.

  • One wave — the case this node was built for, and it is unchanged: the cursors are drawn, draggable and authoritative, and the method only decides where they are first placed.
  • Several waves — each input is cut at a threshold read from its own data: its own histogram, its own 5 % quantile, its own noise. The method stays selectable, because it is the recipe they share; the cursors and the Guess that moves them go grey, because a bound placed by hand could only ever belong to one spectrum while appearing to apply to all of them. Nothing is written into lowBound/highBound, so pulling the second cable out gives back the window you had placed by hand.
  • The output is one trimmed wave per input wave, in input order, each carrying the title of the spectrum it came from in its source metadata.
  • The frame shows the first input's histogram — there is one frame and one set of bars, and one spectrum's worth of bars is what can honestly be drawn — and the counter reads N entrées · kept/total, the totals being summed over the batch.
  • One input the kernel fails on is one broken result, not a dead node: it is logged and the resolve carries on. error appears only when nothing came out.

Methods

All three share the same contract: they return the value the lower cursor should be seeded at, or an infinite bound meaning “no opinion”. The cut itself does not know which method produced the bound.

Method Behaviour
passthrough Cuts nothing. Returns an infinite low bound, which the shell maps onto the frame bottom, so the whole wave comes through.
intensityThreshold The simplest method: the threshold is the cursor. An explicit threshold seeds it; otherwise the node places it under the 5 % lowest points, read off the histogram it has already computed.
madResidual Estimates the noise from the data and places the cursor above it. See below.

Algorithm — k·MAD on the moving-average residual

The method is a relative rejection test on the intensity axis. It proceeds in three steps, all in Rust.

  1. Moving-average residual. A centred moving average of width window slides along the Y block and, for each point, the difference between its value and the mean of its neighbourhood is recorded. A real peak deviates strongly, background noise barely at all. The two ends have no full window and borrow the nearest partial average — padding with zeros would invent a step at each border and a false noise floor. Prefix sums keep this O(n) whatever the width.
  2. Robust noise estimate. The median of the absolute residuals is taken and multiplied by 1.4826, the conversion factor from a median absolute deviation to a standard deviation for a normal distribution. The median, rather than the mean, is what makes this robust: a few intense peaks cannot inflate the estimate the way they inflate a variance. window below 3 is clamped up, since a window of 1 would make the residual identically zero.
  3. Threshold. The cursor is placed at baseline + k × σ, where the baseline is the median of the intensities. The + baseline is essential, not cosmetic: σ measures a spread around a level, so an absolute k × σ cut would sit at 0 and would either remove nothing or erase the whole signal, depending on the scale of the data. A median baseline, in turn, cannot be dragged upward by a minority of large peaks, so the peaks do not raise the very threshold meant to isolate them.

The window is counted in samples, not in physical units: it covers a shorter span of the acquisition on a dense spectrum than on a sparse one. It is reproducible for a given dataset, but not comparable across acquisitions with different sampling.

k is the rejection multiplier — the analogue of the multiplier used in any Gaussian rejection test. It means nothing on its own: it is not a threshold, only a factor applied to σ, and it is only meaningful because the cursor it seeds remains draggable afterwards. For reference, a Gaussian test keeps about 95 % of a normal population at 1.96σ and about 99.3 % at 2.58σ; the default k = 5 is deliberately far more conservative, which suits spectra whose signal is sparse.

Histogram

The frame displays the distribution of the input intensities, computed on the Y block before any trimming: the cursors are placed on the input distribution, not on the already-cut one.

  • Log scale. Bins are evenly spaced in log10(value), one bar per fraction of a decade, and bar centres are geometric means — an arithmetic midpoint would sit at the wrong place on a logarithmic value axis. A linear histogram of a spectrum spanning five orders of magnitude is useless: every bar piles into the first one.
  • Bar count follows the span, at 6 bars per decade, with a floor of 8 and the requested count as a ceiling. A fixed number of log bins would either waste the frame on a narrow spectrum or collapse a wide one into a handful of occupied bars.
  • Non-positive values have no logarithm and are left out of the log histogram; the kernel reports how many, so the shell never displays a distribution that silently does not add up.
  • The count axis is logarithmic as well. A spectrum with a 1959-point noise floor and 1-point peaks renders the peaks as sub-pixel slivers otherwise.

Interactive behaviour

  • The frame shows the histogram plus the two cursors, each carrying a numeric field on its own line. Dragging a cursor, typing a value, changing k, changing window or changing the method all re-run the cut, republish the output and re-resolve the children.
  • Both bounds are authoritative. A finite cursor is exactly what defines the trim, so the lower cursor can be dragged below a guessed threshold and the upper one can cut from above. The method only seeds a bound that is absent.
  • User adjustments persist. A re-resolve with unchanged parameters must not move a hand-placed cursor; only an unset bound is seeded. Changing k or window does move the cursor, because that is a deliberate request to see where the method puts the threshold. Every bound change is undoable.
  • Dragging fires dozens of events per second: the cursor follows the pointer immediately and the kernel runs once, on a short debounce, so a drag costs a single cut instead of one per frame. A ticket counter discards results from superseded runs.
  • A live kept / total counter distinguishes a real trim from a no-op, which the cursors alone cannot show.

Error conditions

  • error more than one link connected to input 0, or a link targeting a removed input. Fan-out on the output is allowed and is not an error.
  • floating no wave connected yet, or the connected value carries no usable wave.
  • fallback WebAssembly or workers unavailable: an equivalent JavaScript implementation is used.

Session behaviour

The method, the two bounds, the method parameters and the display scale are serialised with the session and restored on reload, so a hand-adjusted trim is never silently recomputed.

Data flow

input wave core
   → kernel: trim_histogram(core, stride, bins, scale)
   → centres, counts, dropped          (frame, no cut)
   → kernel: trim_guess(core, stride, method, k, window, threshold)
   → one f64: where the lower cursor goes
   → kernel: trim_apply(core, stride, lowBound, highBound)

The guess returns a single number and allocates nothing: it is the only threshold the shell needs, so the kernel does not build and copy a trimmed point set just to read it back. The cut, trim_apply, takes the two bounds and knows nothing about methods, parameters or guesses — which is what keeps the two roles from being confused. A NaN intensity is never kept, since it would poison the output.

F-KMD Kendrick defect axis

Rescales a spectrum around a reference m/z that you obtain by typing a chemical formula, and reports the mass defect of every peak on that new scale. The formula is the only parameter: it is read, converted to an m/z, and that single number drives the whole transform.

The point of the operation is comparison. Peaks that differ from the reference by a whole number of mass units land on the same rescaled value, so homologous series — a family of compounds differing by CH2, for instance — collapse onto one another, and what is left on the defect axis is the part that is chemically not explained by that difference.

Item Specification
Inputs 1 input — one or more XY waves, read as X = mass and Y = intensity.
several links more than one link may target input 0. Each input wave is treated independently and produces its own product; nothing is merged.
Outputs 1 output — one product wave per input wave, as a non-interleaved 2D wave [X…, Y…].
X is the rescaled mass, Y is the mass defect.
Input layout 2D only: [x0, x1, ..., y0, y1, ...], where x is a mass and y an intensity.
A wave that is not XY is refused and counted in the node readout, rather than silently dropped.
Parameters notation — the formula, as typed. This is the only parameter; everything else in the output follows from it.
Output metadata Every product carries the formula it was built from and the m/z that was applied, so a wave can always be traced back to the reference that produced it: "f-kmd": true, key (the notation as typed) and mz.

Writing the formula

The formula is written as a composition, optionally followed by an ionisation in square brackets. The composition says which atoms are present; the bracketed part says which ion is being measured, and it is what makes the m/z correct.

Written Means — the m/z shown is the one the node actually applies
C6H12O6 The neutral molecule — m/z 180.063388
C6H12O6 [H+] Protonated — m/z 181.070665
C6H12O6 [Na+] Sodiated — m/z 203.052609
C6H12O6 [2H+] Deuterated — m/z 182.076941. Written [2H+] and not [H+H+]: inside the brackets, the number before the symbol is a mass number, not a count.
12C6 1H12 16O6 [H+] Monoisotopic glucose — m/z 181.070665, the same as above. Writing the mass numbers pins the isotopes; leaving them out lets the engine choose the most probable one.

Two conventions govern the digits, and they are not interchangeable: a number before a symbol is a mass number (12C), a number after it is an atom count (C6). A mass number that does not exist — [99Na+] — is reported as a typo rather than quietly ignored, since a formula that reads as something else is worse than one that is refused.

What the transform does

The reference m/z defines a scaling factor, round(mz) / m/z, which is computed once and applied to every mass. The mass defect is then read on the rescaled axis, not the original one — that ordering is the whole definition of the operation. 

X' = X × round(mz) / m/z        rescaled mass
Y' = X' − round(X')             mass defect, in [−0.5, +0.5]

With C6H12O6 [H+] as the reference (m/z 181.070665, factor 0.999609738):

Original m/z Rescaled X Defect (Y)
100.0000 99.9610 −0.0390
200.0000 199.9219 −0.0781
300.0000 299.8829 −0.1171
453.2401 453.0632 +0.0632

An m/z that is already a whole number gives a factor of exactly 1: the masses pass through unchanged, and the output Y is simply the plain mass defect.

Interactive behaviour

  • The readout shows the formula as it is read — composition, charge and m/z — so a misspelled symbol is caught while typing, before anything is computed.
  • Typing updates that readout only. Enter applies the formula: the rescaling runs on every input wave, and the nodes downstream are refreshed. A commit therefore does exactly one pass over your data, however many spectra are linked.
  • Several links may share the input anchor. They are processed one after another, each producing its own product wave, so comparing the same reference across a batch is a matter of linking several inputs.
  • A spectrum that fails is reported without stopping the others; a partial result is still a result, and the node only turns red when nothing at all could be produced.

Error conditions

  • error the formula cannot be read — unknown element, or a mass number that does not exist. The message is shown in the node and no product is published.
  • error the reference m/z cannot define a scale. In practice this means an m/z that is not a positive number; nothing is published rather than a spectrum with the wrong axis.
  • floating no formula read yet, or no input wave connected. The node needs something to work on before it has anything to give.
  • not XY an input that is not an XY wave is skipped, and the count is displayed so a short output is never a mystery.

Session behaviour

The formula is serialised with the session and restored on reload. The products are not: they are recomputed from the formula and the input waves when the pipeline next runs, so a restored session can never display products made from a different reference.

Reading the result

The output is a derived product: it exists on the mass axis alone, and it is meant to be examined on its own. The mass defect is a property of the mass, not of the peak — two peaks sharing a mass share their defect whatever their heights — so the wave you get out is deliberately not the spectrum you put in, and its Y axis is the defect, on a completely different scale from any intensity.

  • Y is the defect, in [−0.5, +0.5]. A node that thresholds intensities — the Trimmer, for instance — has nothing meaningful to cut here. Threshold on the Trimmer before this node, where Y still holds intensities, and use the output for what it is: a rescaled mass axis and its defects.
  • Intensities are not carried over. One input point gives one output point, and that point carries the defect. The input wave is left untouched, so the intensities remain available on it — and on every other branch that consumes it.

Attribution exhaustive mixed-radix

Given a spectrum (XY peaks), a list of combining groups (neutral bricks: CH2, O, NH, C…) and a list of ionising groups (adducts: [H+], [Na+], [2+]…), this node enumerates every valid combination of those groups whose mass falls inside a ppm window around each peak. It is not a random sampler and not a heuristic: the space is walked exhaustively by a mixed-radix counter (odometer-style iteration over the Cartesian product of each group's allowed multiplicities), with a canonical form that guarantees each chemical formula is reached exactly once despite isotopic dependencies.

The engine is written in Rust, compiled to WebAssembly, and runs in a dedicated worker pool — the main thread never blocks. A JavaScript fallback implements the identical algorithm (proven by parity tests) for environments without WASM or workers. An alternative heap-based strategy (`cribleHeap`) exists for best-first enumeration but is not the default.

The enumeration — mixed-radix counter (odometer)

The combining groups and ionising groups each define a radix (the number of allowed counts for that group, from min to max). A combination is a vector of indices [i₀, i₁, …, iₙ]. The mass of a vector is the dot product of its counts with the precomputed group masses (including the chosen isotope per group). The caps are precomputed per-group maxima derived from the global maxMass (highest peak + ppm window), so groups that cannot possibly fit are capped at 0.

  1. Fixed groups (min=max) are eliminated from the iteration. Their mass is added as a constant offset; only their isotope choice (if ratio<1) is iterated. This removes entire dimensions from the counter.
  2. Recursive odometer. A depth-first recursion steps through each group's allowed counts (0..cap). At the leaf (all groups decided), the total mass is checked against minMass (floor) and maxMass (ceiling). States within the window are emitted.
  3. Canonical form for isotopic dependence. When the plan contains a group and one of its sub-groups (e.g. CH2 and C, or 13CH2 and 13C), different index vectors can yield the same chemical formula (e.g. 13CH2 + 12C == 13C + 12CH2). The engine detects the dependence by comparing signed, unreduced composition difference vectors between pairs of bricks. If two distinct pairs share the same delta and all four bricks have distinct compositions, a canonical form is enforced at the decidedAt digit (the highest index of the four bricks): one of the two take bricks is forced to zero. This removes duplicate formulas without discarding valid combinations.
  4. Mass window per peak. For each peak mass m, the floor and ceiling are m ± ppm × m / 1e6 (with a 1e-3 Da absolute floor tolerance so a formula sitting exactly on the boundary is kept). The global ceiling (highest peak + window) drives the per-group caps. The floor is applied only at the leaf (final mass is definitive).
  5. Sorting & matching. Emitted states are sorted by mass at the end (O(k log k)). The spectrum's peaks are sorted once by mass. Each formula is matched to its nearest peak by binary search (O(log n)). If the error in ppm is within the window, the formula is a candidate. The bestMatches parameter keeps the top-N distinct formulas per peak by log-probability (the probability comes from the product of group log-probabilities, where ratio controls the isotope distribution).

Alternative strategy: heap-based best-first (cribleHeap). A min-heap on mass expands the lightest state first, using a bitmap/Set for deduplication (canonical form applied at push time). It visits states in strictly increasing mass order and can stop early, but requires a visited set. The mixed-radix counter is the default because it avoids the visited-set overhead and is faster for full-window enumeration.

Why not naïve brute force?

A naïve Cartesian product of all group counts explodes combinatorially. With 4 combining groups each allowed 0..50 and 1 adduct 1..1, the raw space is 51⁴ ≈ 6.7 million combinations — but the mass window (via per-group `caps` computed from `maxMass`) restricts it to a thin shell. The mixed-radix counter iterates only combinations within those caps, skipping fixed groups (min=max) entirely. On a 95-peak spectrum (175–389 Da, [H+]) with groups CH2, NH, O, C the engine visits ~29,000 states and produces ~300 attributed formulas in ~10 ms (Rust/WASM) or ~50 ms (JS fallback) — compared to seconds or memory exhaustion for an unbounded product.

Session behaviour

The two group tables (combining, ionising), global ratio, charge min/max, bestMatches, ppm, and the stale flag are serialised. Calibration error surface least squares

Reference points

A reference point is one attribution result: the true m/z of the formula, the measured m/z of its peak, that peak's intensity, and the errorPpm between them. Two ways to obtain them:

  • From the collection (useCollectionErrors on): every entry carrying a formula, a matched target and a finite error is taken as stored. This is the honest path — the error is the one the sieve measured, not one recomputed here.
  • Recomputed (checkbox off, or the Recompute refs button): for each formula, the closest spectrum point within 0.5 Da becomes the reference and the error is recomputed as (measured − true) / true × 106. Use it when the collection's targets are stale — after the spectrum upstream changed.

Fewer than 3 usable reference points and the node refuses to fit: a plane through two points is not a calibration, and three is the least that can be checked. The message says so instead of drawing a confident line through nothing.

The fit, and what it does

  1. Least squares in Rust. The design matrix is built from the mode's powers of mass and intensity, the normal equations are solved by Gaussian elimination, and the kernel returns the coefficients with the RMSE of the fit. A singular system falls back to the identity [1, 0] rather than to noise.
  2. 1D modes fit positions: measured → true directly, and the corrected axis is the polynomial evaluated at each point.
  3. 2D modes fit the error surface: the polynomial predicts errorPpm from (m/z, intensity), and the correction is applied as x′ = x / (1 + errorPpm/106) — the error is a relative offset, so one surface applies across the whole range.
  4. Apply in the worker. The corrected X comes back from calibrationApply(2D) and is re-paired with the untouched Y; a result shorter or longer than the input is truncated to the common length, so an odd wave size can never produce a misaligned core.

Interactive behaviour

  • The graph overlays four things, each with its own toggle: the raw spectrum (grey), the corrected one (green), the residuals — one red dashed stick per reference, from measured to corrected — and, for 2D modes, the error surface as a 30 × 20 heat grid over the reference extent.
  • The readout shows the fitted coefficients, the RMSE in ppm and the number of reference points — the three numbers that decide whether the fit can be trusted.
  • Multiplexed, the mode selector and Recompute refs go grey (one batch, one treatment), and the readout becomes N entrées · X pts totaux.
  • Changing the mode or pressing Recompute refs refits immediately and re-resolves the children.

Error conditions

  • error a link targets an input the node does not have — only inputs 0 and 1 are read.
  • error fewer than 3 usable reference points, or the fit itself fails: nothing is published rather than a wrongly-scaled spectrum.
  • floating no FormulaCollection and/or no spectrum connected yet.
  • kernel error one spectrum of a batch failed — the others still publish; the node turns red only when nothing came out.
  • fallback WebAssembly or workers unavailable: the same fit and apply run in JavaScript on the calling thread.

The terminal display node: every wave reaching its single input becomes a trace on a WebGL frame that fills the central dialog, and an inspector in the right panel drives the drawing. It writes nothing — it is the end of a branch.

Item Specification
Inputs 1 input — any number of links, and any number of waves per link. Each wave becomes one trace, coloured from a six-colour palette in link order.
Outputsnone — a display sink.
Inspector Traces — colour picker, name with its point count, hide/show, and drag to reorder the drawing stack. Selecting a trace opens its editor: mode (lines between points, lines + points, points only, sticks to zero), layer (Canvas/WebGL for massive clouds, SVG for interactive traces), marker shape and size, line size.
Axes — per axis: show/hide, label, and a range as a dual slider backed by two numeric fields, with an automatic-bounds button. Mirrored axes follow their source and carry a label only.
Scale Linear or logarithmic on both axes; a log view containing non-positive values falls back to linear automatically rather than drawing an empty frame.
Session behaviour Axes and per-trace options (colour, mode, layer, marker, order) are serialised and re-applied on the next resolve, matched by trace id first and by title second, so a rename does not reset your colours.

Status: floating while nothing is linked, resolved with at least one trace, error when a resolve produced none.

Chat tools WebSocket

A chat room for discussing a session with whoever else is looking at it. The node carries no flow anchors: it opens a draggable, foldable dialog — a Dialog, not an accordion, because a chat that collapses when the panel scrolls away would be unusable — with a connection bar, a log, and a one-line input.

Item Specification
Inputs / Outputsnone — it talks to a server, not to the flow.
Parameters url — the WebSocket endpoint; empty means the page's own host, with wss on https and ws on http (a secure page may not open an insecure socket).
nick — the name you post under.
room — the room to join; empty shows the server's room list with its user counts, one click to join.
Behaviour Join performs a full reconnect — URL or nick may have changed, and the old socket points at the wrong place. Reconnection is exponential and capped at 10 attempts: a server that is down must not leave a retry loop running in a background tab for the rest of the session. Enter sends (max 500 characters) and never inserts a newline; the input is cleared only on a successful send, so a message typed on a dead socket is not thrown away. Log lines are inserted as text, never markup — a chat room is untrusted input.
Status resolved while connected, floating otherwise — the node's own colour follows the socket even when the dialog is hidden behind something else.
Session behaviour Only url, nick and room are serialised; the socket, the log and the retry counter belong to the visit. The chat is not reopened on reload: a page that starts talking to a server on its own is a page that cannot be opened quietly. The fields come back filled in, and you press Join — which is also the only moment a nick is really yours. Deleting the node closes the socket and clears any pending retry.
